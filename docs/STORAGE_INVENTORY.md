## 统计口径

- GB = 1,000,000,000 字节；GiB = 1,073,741,824 字节。MB = 1,000,000 字节。
- 模型：早期清单取自 Hugging Face 文件元数据的原始字节数；Demucs 使用官方下载地址的 HTTP `Content-Length`。随后安装时已逐个核对实际大小与哈希，并记录到 `models/install-manifest.json`。
- Python 包下载：PyPI 指定版本、匹配 macOS arm64 / Python 3.10 的安装包字节数。
- wheel 解压文件：读取 ZIP 中央目录，累加各文件的未压缩大小；不是安装后的磁盘占用。
- 本机已安装内容：`du -sk` 的结果乘以 1024，表示文件系统分配的空间。
- Hugging Face 直连超时，本次文件元数据通过 `hf-mirror.com` 镜像接口取得；报告保留仓库 revision、官方文件链接及元数据提供的 SHA256。
- 模型 revision 是本次核对的快照。下载脚本检查默认分支是否仍为该 revision；上游加载代码使用默认分支缓存，文件齐全后由本项目启用离线加载，避免推理时更新权重。后续在线补齐若文件发生变化须重新核对。

## 音频为什么会持续增长

模型供所有音色和歌曲共用。新增参考音色不需要另训练或下载一套模型；空间增长主要来自原始素材、分离音轨、不同参数版本和导出作品。

无压缩 PCM 音频的数据大小可以精确计算：

```text
采样率 × 声道数 × 每个采样的字节数 × 秒数
```

以恰好 240 秒、44,100 Hz 的音频为例，以下为音频数据，不含 WAV 文件头及元数据：

| 格式 | 精确音频数据字节 |
| --- | ---: |
| 16-bit 双声道 PCM | 42,336,000 |
| 24-bit 双声道 PCM，本项目 WAV 导出格式 | 63,504,000 |

100 份这样的 24-bit WAV 导出作品，仅音频数据就有 6,350,400,000 字节。原唱、人声、伴奏和其他版本需要分别计算；不能在未知格式、时长和版本数量时给一个固定的每首总占用。

成功任务会清理临时副本，保留已发布素材与作品；失败、取消任务的临时文件会保留用于排查，因此会影响峰值和剩余空间。

## 复核命令

```sh
uv run python scripts/audit_storage.py \
  --hf-endpoint https://hf-mirror.com \
  --output docs/storage-audit.json \
  --packages-output docs/STORAGE_PACKAGES.md
```

此命令仅读取远程元数据和 wheel ZIP 中央目录，不安装推理包或下载模型权重。检查报告的 `completeness` 字段；任何查询失败时，总数只包含成功项，不能视为完整清单。重新生成后须同步更新本说明中的快照数值。
